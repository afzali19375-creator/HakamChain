# حَکَم‌چین (HakamChain) — MVP

> **لایه داوری و امانت‌داری (Escrow) با حاکمیت قضایی فقهی** — دموی MVP روی شبکه آزمایشی **Ethereum Sepolia**.
> در این نسخه، پلتفرم نقش **حَکَم** را بازی می‌کند: پول در قرارداد هوشمند قفل می‌شود، اگر اختلاف پیش بیاید تیم فقهی/فنی اسناد را بررسی می‌کند و پلتفرم با امضای تراکنش، وجه را از ولت قرارداد به ولت **برنده** منتقل می‌کند.

> ⚠️ **این یک دموی تست‌نت است.** سقف هر امانت‌گذاری (حاشیه امن) **0.05 ETH** است و هیچ وجوه واقعی نباید درگیر شود.

## ۱. ایده از کجا آمد؟ (تحلیل Kleros، UMA و Reality.eth)

سه پروتکل شناخته‌شده‌ی داوری/اوراکل، چهار جزء مشترک دارند:

| پروتکل | سازوکار حل اختلاف | منبع اعتماد | اجرای حکم |
|---|---|---|---|
| **[Kleros](https://kleros.io)** | دادگاه غیرمتمرکز؛ هیئت‌منصفه با سهام‌گذاری PNK به‌صورت تصادفی (Sortition) انتخاب می‌شوند، شواهد را می‌بینند و رای می‌دهند؛ رای اکثریت اجرا می‌شود و رای ناهمسو با اکثریت، سهم هیز (stake) او را کسر می‌کند؛ امکان تجدیدنظر با دورهای بزرگ‌تر | انگیزه‌های رمزارزی (crypto-economics)، بدون واسطه انسانی مرکزی | خودکار توسط قرارداد Arbitrable (ERC-792) |
| **[UMA](https://uma.xyz)** | اوراکل خوش‌بینانه (Optimistic Oracle): یک «ادعا + وثیقه» ثبت می‌شود؛ اگر در بازه چالش کسی مخالفت نکند، درست فرض می‌شود؛ در صورت اختلاف، صاحبان توکن UMA در DVM با رای‌گیری (Commit/Reveal، اکثریت ۶۵٪) تصمیم می‌گیرند | رای‌گیری سهام‌داران + جریمه رأی خلاف اکثریت | خودکار روی زنجیره |
| **[Reality.eth](https://reality.eth.limo)** | بازی صعودی پاسخ‌ها: سؤال + وثیقه؛ هرکس پاسخ بهتری با وثیقه بالاتر بدهد، پاسخ قبلی را ساقط می‌کند؛ پس از پایان بازه‌ها، آخرین پاسخِ سربه‌سر «پاسخ نهایی» است؛ در صورت نیاز، داور نهایی (مثلاً Kleros) تصمیم می‌گیرد | بازی وثیقه‌ها + داور اختیاری | فراخوانی قرارداد سؤال‌کننده |

**الگوی مشترک:** قفل وجه در قرارداد ← ثبت شواهد (هش روی زنجیره، سند آفلاین) ← فرایند حل اختلاف ← اجرای خودکار حکم.

**جایگاه حَکَم‌چین:** به‌جای هیئت‌منصفه توکنی (Kleros) یا بازی وثیقه‌ای (Reality/UMA)، داور یک **حاکمیت قضایی فقهی مورد اعتماد** است — مشابه نهاد **تحکیم** در فقه: طرفین مال را پیش امانت‌دار می‌گذارند، اختلاف با **بینه** (شواهد) بررسی می‌شود و حکم صادر و اجرا می‌گردد. این مدل برای داوری قراردادهای کوچک فارسی‌زبان سه مزیت دارد:

1. **حریم خصوصی:** اسناد محرمانه هرگز آپلود نمی‌شوند؛ فقط هش SHA-256 آن‌ها ثبت می‌شود تا اصالت قابل اثبات باشد.
2. **فهم پذیرش‌کنندگان:** داوری با زبان و منطق فقهی/حقوقی، نه با توکن و بازی اقتصادی.
3. **شفافیت زنجیره‌ای:** هر حکم، یک تراکنش قابل ممیزی روی بلاکچین است (پول از قرارداد به برنده).

> **مسیر تکامل (Roadmap):** چند‌امضایی‌کردن شورای داوری (Multi-sig) ← داوران سهام‌گذار با مدل Kleros ← لایه خوش‌بینانه برای اعتراض‌ها (مدل UMA/Reality).

## ۲. معماری MVP

```
┌─────────────────────────── مرورگر (EJS + Tailwind, RTL) ───────────────────────────┐
│  پورتال کاربر (/portal)                      پنل حَکَم (/admin)                      │
│  • اتصال MetaMask (SIWE)                     • لاگین SIWE (فقط ADMIN_ADDRESSES)     │
│  • ایجاد پرونده + قفل وجه                    • لیست پرونده‌های در جریان              │
│  • اعلام اختلاف / بارگذاری هش شواهد          • شواهد (هش‌ها) + دکمه‌های صدور حکم      │
└──────────────────────────────┬────────────────────────────────┬────────────────────┘
                               │ fetch (JSON)                   │
┌──────────────────────────────▼────────────────────────────────▼────────────────────┐
│                            بک‌اند Node.js / Express                                  │
│  routes → controllers → services                                                   │
│  • SIWE (EIP-4361) با ethers.verifyMessage + nonce یک‌بارمصرف در سشن امضاشده         │
│  • Sequelize + SQLite: Users / Cases / Evidence                                    │
│  • blockchainService (ethers.js v6):                                               │
│      - ساخت calldata برای ولت کاربر (createEscrow / declareDispute)                 │
│      - راستی‌آزمایی تراکنش‌های کاربر از روی Event های زنجیره                          │
│      - اجرای حکم: releaseFunds() با ولت ادمین (ADMIN_PRIVATE_KEY در .env)           │
└──────────────────────────────┬─────────────────────────────────────────────────────┘
                               │ JSON-RPC (Sepolia)
┌──────────────────────────────▼─────────────────────────────────────────────────────┐
│              قرارداد هوشمند IslamicEscrow.sol  (OpenZeppelin: Ownable +            │
│              ReentrancyGuard) — سقف واریز 0.05 ETH، رویدادهای کامل                 │
└────────────────────────────────────────────────────────────────────────────────────┘
```

**جریان دمو (گام‌به‌گام):**

1. **کارفرما** وارد `/login` می‌شود (امضای SIWE)، در `/portal` پرونده می‌سازد و با تایید تراکنش در MetaMask، وجه را در قرارداد قفل می‌کند → رویداد `EscrowFunded` ثبت و پرونده با وضعیت «سپرده‌شده» در دیتابیس ذخیره می‌شود.
2. هر طرف می‌تواند **شاهد** بارگذاری کند: هش SHA-256 فایل در مرورگر ساخته می‌شود (فایل هرگز آپلود نمی‌شود) و در جدول Evidence ثبت می‌گردد.
3. در صورت اختلاف، یکی از طرفین دکمه «اعلام اختلاف» را می‌زند → تراکنش `declareDispute` روی زنجیره و وضعیت پرونده «در جریان داوری» می‌شود.
4. **ادمین (حَکَم)** با ولت مجاز وارد `/admin` می‌شود، شواهد را می‌بیند، مبنا را می‌نویسد و یکی از دو دکمه را می‌زند:
   - «تایید و بازپرداخت وجه به کارفرما» → `releaseFunds(id, true)` → رویداد `FundRefunded`
   - «تایید و آزادسازی وجه به مجری» → `releaseFunds(id, false)` → رویداد `FundsReleased`
5. تراکنش از ولت ادمین ماین می‌شود و وجه مستقیماً از ولت قرارداد به ولت برنده منتقل می‌شود (در MetaMask قابل مشاهده است).

## ۳. راه‌اندازی

### پیش‌نیازها

- **Node.js ≥ 18.17** (تست‌شده با Node 24)
- **MetaMask** (یا هر کیف پول تزریقی EVM)
- کمی **Sepolia ETH** برای دو ولت (کارفرما و ادمین) از فاست‌های رایگان:
  - <https://sepoliafaucet.com> ، <https://faucet.sepolia.dev> ، <https://cloud.google.com/application/web3/faucet/ethereum/sepolia>
- یک **RPC** Sepolia (بدون کلید هم می‌شود: `https://ethereum-sepolia-rpc.publicnode.com`)

### نصب

```bash
git clone https://github.com/afzali19375-creator/HakamChain.git
cd HakamChain
npm install
cp .env.example .env
```

### تنظیم `.env`

```bash
# یک سکرت تصادفی بسازید
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

| متغیر | توضیح |
|---|---|
| `SESSION_SECRET` | سکرت امضای کوکی سشن (الزامی) |
| `RPC_URL_SEPOLIA` | نقطه RPC شبکه Sepolia |
| `ADMIN_PRIVATE_KEY` | کلید خصوصی **ولت ادمین (حَکَم)** — فقط تست‌نت! (برای امضای تراکنش آزادسازی) |
| `ADMIN_ADDRESSES` | آدرس(های) مجاز ورود به پنل حَکَم، با کاما جدا شده و حروف کوچک |
| `CONTRACT_ADDRESS` | بعد از دیپلوی پر می‌شود |
| `DB_STORAGE` | مسیر فایل SQLite (پیش‌فرض `./data/hakamchain.sqlite`) |

> 🔐 **هرگز** `.env` را کامیت نکنید و کلید اصلی کیف پول شخصی‌تان را وارد نکنید؛ یک ولت «مصرفی» مخصوص تست‌نت بسازید.

### دیپلوی قرارداد

```bash
npm run compile        # کامپایل Solidity
npm run test:chain     # اجرای تست‌های قرارداد (Hardhat درون‌حافظه‌ای)
npm run deploy:sepolia # دیپلوی روی Sepolia (نیازمند ADMIN_PRIVATE_KEY و گاز)
```

خروجی اسکریپت دیپلوی، آدرس قرارداد را چاپ و در `deployments/sepolia.json` ذخیره می‌کند. آن را در `.env` بگذارید:

```
CONTRACT_ADDRESS=0x…
```

> نکته: ادمین قرارداد (owner) همان ولتِ `ADMIN_PRIVATE_KEY` است؛ پس بهتر است قرارداد را با همان ولت ادمین دیپلوی کنید.

### تست خودکار انتها-به-انتها (بدون نیاز به MetaMask)

برای اطمینان از سلامت کل سیستم (قرارداد + بک‌اند + پنل) یک تست E2E کامل روی زنجیره محلی Hardhat فراهم شده است:

```bash
npm run test:chain     # ۱) تست‌های واحد قرارداد هوشمند
bash test/run-e2e.sh   # ۲) تست E2E: زنجیره محلی → دیپلوی → سرور → ۳۶ سناریو
```

تست E2E کل چرخه واقعی را شبیه‌سازی می‌کند: ورود SIWE با امضای واقعی ولت، واریز `createEscrow` روی زنجیره، تأیید تراکنش توسط بک‌اند، ثبت مدرک (فقط هش SHA-256)، اعلام اختلاف، اجرای حکم ادمین از طریق ولت بک‌اند و بررسی انتقال واقعی وجه به کیف برنده — به‌همراه سناریوهای نفوذ (امضای جعلی، txHash ساختگی، دسترسی غریبه، حکم دوباره).

### اجرا

```bash
npm start        # یا: npm run dev (با ری‌استارت خودکار)
# → http://localhost:3000
```

### تست فلو دمو

1. دو ولت بسازید: **کارفرما** و **مجری** (هر دو با Sepolia ETH برای گاز) + ولت ادمین.
2. `ADMIN_ADDRESSES` را برابر آدرس ولت ادمین بگذارید، سرور را اجرا کنید.
3. با ولت کارفرما وارد شوید، پرونده بسازید و وجه را قفل کنید (MetaMask).
4. از دو طرف شواهد اضافه کنید؛ در صورت نیاز «اعلام اختلاف» بزنید.
5. با ولت ادمین وارد شوید (`/admin`)، پرونده را باز کنید و «تایید و آزادسازی وجه به مجری» را بزنید.
6. در MetaMask ولت مجری ببینید که موجودی به اندازه امانت (+ بدون کارمزد برای گیرنده) اضافه شده است. لینک تراکنش‌ها در Etherscan Sepolia در پنل موجود است.

## ۵. مرجع API

| متد و مسیر | دسترسی | توضیح |
|---|---|---|
| `GET /api/health` | عمومی | سلامت سرور |
| `GET /api/config` | عمومی | chainId، آدرس قرارداد، سقف واریز، آماده‌بودن web3 |
| `GET /api/auth/nonce?address=0x…` | عمومی | ساخت پیام SIWE + nonce (ذخیره در سشن) |
| `POST /api/auth/verify` | عمومی | تایید امضای SIWE → نشست |
| `GET /api/auth/me` · `POST /api/auth/logout` | نشست | وضعیت کاربر / خروج |
| `GET /api/contracts/create-escrow-params?contractor=0x…` | کاربر | calldata تراکنش قفل وجه |
| `GET /api/contracts/dispute-params?caseId=n` | طرف پرونده | calldata اعلام اختلاف |
| `POST /api/cases` | کاربر | ثبت پرونده پس از واریز (راستی‌آزمایی `EscrowFunded` روی زنجیره) |
| `GET /api/cases` · `GET /api/cases/:id` | کاربر | پرونده‌های من / جزئیات |
| `POST /api/cases/:id/dispute` | طرف پرونده | تایید تراکنش `DisputeDeclared` و تغییر وضعیت |
| `POST /api/cases/:id/evidence` | طرف پرونده / ادمین | ثبت **فقط هش SHA-256** شواهد |
| `GET /api/admin/cases` · `GET /api/admin/cases/:id` | **ادمین** | لیست و جزئیات همه پرونده‌ها |
| `POST /api/admin/resolve` | **ادمین** | صدور حکم: فراخوانی `releaseFunds` با ولت ادمین |

## ۶. نکات امنیتی پیاده‌سازی‌شده

- **کلید خصوصی فقط در `.env`** (در گیت و کد هرگز) — `.gitignore` آن را مسدود می‌کند؛ `.env.example` الگوی امن است.
- **SIWE با nonce یک‌بارمصرف** در کوکی سشن امضاشده (HttpOnly, SameSite=Lax)؛ دامنه/زنجیره/انقضای پیام سمت سرور اعتبارسنجی می‌شود.
- **سقف واریز روی زنجیره** (حاشیه امن 0.05 ETH) + بازرسی سمت سرور قبل از ثبت پرونده.
- **راستی‌آزمایی تراکنش کاربر از روی Event** — کلاینت نمی‌تواند مبلغ/طرفین را جعل کند؛ دیتابیس آینه زنجیره است.
- **حریم خصوصی شواهد:** فقط هش SHA-256 (محاسبه در مرورگر با WebCrypto) ذخیره می‌شود؛ خود فایل هرگز به سرور نمی‌رسد.
- **کنترل دسترسی دو لایه:** `requireAuth` برای کاربران و `requireAdmin` برای همه مسیرهای `/api/admin/*` + گارد صفحات.
- **Helmet با CSP بدون inline-script**، rate-limit روی `/api` و `/api/auth`، خطای‌های JSON ساخت‌یافته، شمارش‌پذیری با `ReentrancyGuard` و custom errors در قرارداد.
- قرارداد `receive/fallback` ندارد تا واریز تصادفی مستقیم ETH رد شود؛ `releaseFunds` فقط با `onlyOwner` و یک‌بارمصرف به ازای هر پرونده.

## ۷. نقشه راه پس از MVP

1. **شورای داوری چند‌امضایی:** حکم با امضای k از n عضو فقهی (Gnosis Safe یا قرارداد سفارشی).
2. **داوران سهام‌گذار:** الهام از Kleros (انتخاب تصادفی + جریمه رأی ناهمسو) با سلب‌علاقه‌سازی فقهی مناسب.
3. **لایه خوش‌بینانه اعتراض:** بازه چالش قبل از اجرای حکم (الهام از UMA/Reality.eth).
4. **زنجیره‌های ارزان‌تر + توکن امضای دیجیتال اسناد** و اتصال به سامانه‌های احراز هویت ایرانی.

## ۸. سلب مسئولیت

این مخزن یک **نمونه اولیه آموزشی (MVP)** روی شبکه آزمایشی است و «مشاوره فقهی/حقوقی» یا محصول مالی محسوب نمی‌شود. پیش از هر استفاده واقعی: ممیزی امنیتی قرارداد (audit)، اخذ مجوزهای قانونی و تایید شورای فقهی الزامی است.
